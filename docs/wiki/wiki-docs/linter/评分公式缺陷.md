# 评分公式缺陷

当前评分公式 `【能力 Lint 概述】` 的核心缺陷。

## 公式

%% [函数得分] = [加权语句数] × [传播能力数] %%

## 缺陷：非组合性

该公式**不是组合的（non-compositional）**——将函数拆分为多个子函数后，总分可能凭空下降。

### 示例

```
方案 A（不拆分）：
  function onMessage() {           // ws=15, caps=[IO,Async]
    await llm.generate(...)
    await send(msg)
  }
  score = 15 × 2 = 30

方案 B（拆成三个）：
  function onMessage() {           // ws=2
    await callLLM()                // → F1
    await sendReply(reply)         // → F2
  }
  function callLLM() { ... }      // ws=8, caps=[IO,Async]
  function sendReply() { ... }    // ws=5, caps=[IO]
  总分 = 2×2 + 8×2 + 5×1 = 25  ← 比重构前更低！
```

拆分应该因为减少能力交叉而降分，但不应该因为"增加函数边界"而降分。

## 后果

- 鼓励开发者将函数拆到极致（每个函数只做一件事、只带最少能力）
- 产生大量 【Pass-through 函数】——自身逻辑为零，只做调用转发
- 【间接税】未被度量：理解一个功能需要追踪十几个函数

## 实例

在 ChatFrame-v11 项目中，一个用户操作"发消息→LLM→回复"跨越 **15 个函数、最长 9 跳**。其中 6 对可以合并的 pass-through 因当前公式鼓励拆分而存在。

## 修复

见【递归组合评分】。
