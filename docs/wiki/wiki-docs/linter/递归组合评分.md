# 递归组合评分

修复【评分公式缺陷】的新评分公式。

## 公式

%% [函数得分] = [own] + Σ_{G ∈ callees(F)} [callee得分(G)] × <DECAY> %%

其中：
- %% [own] = [加权语句数] × [传播能力数] %%（即原公式）
- `<DECAY>` = 衰减因子，建议取值 `0.5`

## 直观含义

> "你的分数 = 你自己的复杂度 + 你委托出去的一半复杂度"

## 性质

1. **拆分不降分**（DECAY > 0）：每多一层委托，多付一次 DECAY 折扣损失
2. **叶子函数不受影响**：没有 callee 的函数得分与当前公式一致
3. **Pass-through 被惩罚**：自身 own≈0 的函数通过继承 callee 分数获得有意义的分值
4. **入口函数得分最高**：级联汇聚所有 callee 分数，反映真实的认知负担
5. **合并 pass-through 降分**：消除一层 DECAY 折扣，总分会下降——正确的重构方向

## DECAY 选择

| DECAY | 效果 |
|---|---|
| 0.1 | 轻微惩罚深层委托 |
| 0.3 | 温和惩罚，保守方案 |
| **0.5** | **推荐值**，清晰区分 pass-through |
| 0.7 | 激进惩罚，显著偏好扁平结构 |

在 ChatFrame-v11 上测试（218 函数）：
- DECAY=0.5：总分 1894.5 → 3360.8（+77%），33 个函数继承率 >75%
- DECAY=0.3：总分 1894.5 → 2623.4（+38%），较温和

## 计算方式

1. 构建调用图（DAG 或含循环）
2. 若无循环：拓扑排序，自底向上一次计算
3. 若有循环：不动点迭代，直到最大变化 < 0.01

## 继承率

继承率 <% `[inherited] / [recursive]` %> 衡量函数有多少分数来自 callee：

- 0%：叶子函数，自己干所有活
- 50%：一半复杂度来自委托
- 100%：纯 【Pass-through 函数】，自身零贡献
