# Linter 修改计划

基于【评分公式缺陷】分析和【递归组合评分】原型验证的后续修改路线。

## 阶段一：递归评分（核心修复）

**目标**：用【递归组合评分】替代当前 `ws × capCount` 公式。

改动范围：
- `src/reporter.ts`：`computeScores` 函数中集成递归评分计算
- 新增拓扑排序/不动点迭代逻辑（处理循环调用）
- CLI 参数：`--decay <value>`（默认 0.5）

预期效果：
- 【Pass-through 函数】不再获得虚假低分
- 入口函数的排名合理上升
- 合并 pass-through 成为有效的降分策略

## 阶段二：Pass-through 诊断

**目标**：新增 `thin_delegate` 诊断类型，显式标记 【Pass-through 函数】。

改动范围：
- `src/analyzer.ts`：新增 `DiagnosticKind.ThinDelegate`
- 检测条件：ws ≤ 3 且 calleeCount = 1 且 own/capRatio > 0.8

预期效果：
- 开发者可直接看到哪些函数是"薄委托"
- 诊断消息建议内联或合并

## 阶段三：递归评分的工具提示

**目标**：更新 `--hint` 系统的提示规则。

改动范围：
- `src/reporter.ts`：新增 `TIP_RULES`
  - `thin-delegate`：提示合并 pass-through 可降分
  - `deep-chain`：提示调用链过深的入口函数
  - `inheritance`：提示高继承率的函数

## 阶段四（可选）：Domain 分析

**目标**：包级 cohesion/coupling 指标（Modularity Q + Conductance）。

改动范围：
- 新增 `src/domain.ts`
- CLI 参数：`--domain` 输出 domain 分析
- 包间调用矩阵热力图

## 参数设计

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--decay` | 0.5 | 递归评分的衰减因子 |
| `--domain` | false | 输出包级 domain 分析 |
| `--hint thin-delegate` | — | 显示 pass-through 合并建议 |
| `--hint deep-chain` | — | 显示深层调用链警告 |
