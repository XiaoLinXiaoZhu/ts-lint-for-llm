# 间接税

函数委托链带来的累积认知成本。

## 定义

每次函数调用委托给另一个函数，就产生一层间接。每层间接的认知成本包括：
- 一个函数名需要记忆
- 一个文件位置需要定位
- 调试时需要多跳一步

## 度量

在【递归组合评分】中，间接税变现为 DECAY 折扣损失：

%% [间接税] = [callee得分] × (1 - <DECAY>) %%

每多一层委托，callee 的分数就打一次折扣。折扣累积 = 间接税。

## 实例

ChatFrame-v11 的 `onMessage` 入口：

```
onMessage (own=3)
  → runAction (own=24)
    → execAction (own=11)
      → doStream (own=13)
        → send (own=10.5)
          → sendOne (own=2) → 外部 IO
```

- 链长：6 跳
- 当前总分：63.5（各函数 own 之和）
- 递归总分（DECAY=0.5）：各级累积衰减，`onMessage` 继承链上所有分数

## 降低间接税

- **合并 pass-through**：消除不必要的委托层
- **减少调用深度**：让高层函数直接调用底层函数
- **扁平的编排**：一个编排函数直接调用 3-4 个叶子函数，而不是链式委托
